# 梗百科 · presents.MemeWiki

给 Alife 的 AI 一个「查梗」的能力：遇到看不懂的网络梗、拼音缩写、圈内黑话，先查再答，而不是凭空编。

移植自 AstrBot 的 `astrbot_plugin_memewiki` 思路（本地词库 + cnmeme.wiki），按 Alife 的模块形态重做：
**不做聊天指令和图片卡，改成 AI 可调用的 XML 函数**，并把信息源从 1 层扩到 4 层。

---

## 它解决什么

模型对「yyds / 你说的对 / 赛博朋克 / 某个刚火三天的梗」这类问题，不查就答，很容易一本正经地编。
另一个极端是「我查不到」——因为大模型的知识截止在半年前，而梗是按天更新的。

这个插件把「查」这件事外包给了一个**四级缓存 + 在线兜底**的检索链路：

```
① 自定义词条  →  ② 内置 6668 条  →  ③ 增量同步库  →  ④ 在线三源
```

- **命中即答**：本地命中 3–20 ms，不联网
- **不命中才联网**：并发查 cnmeme / 百度百科 / 中文维基，谁快用谁
- **实在没有就直说**：不编，让 AI 追问，你解释一次它就能记住

---

## 四层数据

| 层 | 内容 | 说明 |
|---|---|---|
| ① | 自定义词条 | 自己圈子的黑话，优先级最高；AI 可写（`记住梗`）可删 |
| ② | 内置词库 **6668 条** | 随插件分发，gzip 压缩后 3.98 MB，解压后常驻内存 |
| ③ | 增量同步库 | 按 `updated_at` 拉 cnmeme 最新条目（标题 + 摘要），默认每天自动同步 |
| ④ | 在线三源 | cnmeme.wiki（梗库本体）、百度百科（泛知识）、中文维基（背景） |

在线是有条件触发的：**本地没命中**，或**本地条目太薄（总字数 < 150）**才联网。

---

## AI 能调用什么

| 函数 | 作用 |
|---|---|
| `SearchMeme(query)` | 主入口。词或含梗的短句都行：`yyds`、`你刚才那句是什么梗` |
| `RememberMeme(name, meaning)` | 记住自定义词条 |
| `ForgetMeme(name)` | 删掉自定义词条 |
| `RandomMeme()` | 随机一条，用来接话 |
| `MemeWikiStatus()` | 词库条数、在线源、命中率、最新收录日期 |
| `SyncMemeLibrary()` | 手动增量同步（几秒钟） |

模块启动时还会往系统提示注入一段规则：**遇到不认识的梗先查再回、别硬编、查到后用自己的话说**。
不想要可以在配置里关掉。

---

## 检索规则

查询先归一化（全角→半角、去空白与标点、英文小写），再按下列优先级打分：

| 情况 | 分数 | 例子 |
|---|---|---|
| 标题 / slug 完全相同 | 1000 | `尼罗河二圣` |
| 完整标题出现在查询里（取最长） | ≤900 | `你说你是什么冠军` → `你是什么冠军` |
| 标题以查询开头 | ≤800 | `赛博` → `赛博义父` |
| 标题包含查询 | ≤700 | |
| 一字之差（仅当前三类全空时） | ≤500 | `赛博庞克` → `赛博朋克` |

刻意**不做**「查询包含标题」的宽松匹配：`你是什么` 不会命中 `你是什么冠军`，避免把无关长标题当成答案。

## 安装

**通过插件市场**：Alife → 系统管理 → 插件市场 → 找到「梗百科」→ 安装。

**手动**：把 `presents.MemeWiki` 整个文件夹放进

```
<Alife 数据目录>\Storage\Plugins\
```

然后重启客户端。

启用：角色设置 → 模块 → 勾选「梗百科」（分组 `presents/梗与黑话`）。

## 用法示例

```
你：yyds 是什么意思
AI：（调用 SearchMeme）「永远的神」的拼音缩写，2020 年前后从电竞圈流行开……
你：刚才那个「你说的对」是什么梗
AI：（查不到 → 追问）这个我确实没查到权威解释，你能说说是哪个语境下的吗？
你：就是不管对方说啥都回"你说的对"
AI：（调用 RememberMeme）记下了，以后我遇到这个用法就懂了
```

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| 联网补充 | 开 | 关掉后完全离线，只认内置库和自定义词条 |
| 查 cnmeme.wiki | 开 | 梗库本体，网络梗最全 |
| 查百度百科 | 开 | 泛知识、人物、流行语 |
| 查中文维基 | 开 | 背景补充；消歧义页会自动跳过 |
| 联网超时（秒） | 8 | 单个数据源的超时 |
| 回答长度上限 | 1500 | 投给对话的文本上限，太长会顶满上下文 |
| 模糊匹配 | 开 | 允许一个字之差 |
| 查「最新收录」 | 开 | 搜索索引没更新的新梗，改从最新列表里捞 |
| 自动同步新梗 | 开 | 启动时若超 12 小时未同步，后台增量同步一次 |
| 走系统代理 | 关 | 默认直连；代理规则没覆盖 cnmeme 时反而更慢 |
| 注入接梗提示 | 开 | 往系统提示里加「先查再答」的规则 |

## 隐私与网络

- 查询词会发给上表里启用的在线源（cnmeme / 百度 / 维基），仅此而已
- 不上传聊天记录、角色设定、本地路径
- 词库、增量库、自定义词条全部存在本地插件目录
- 关掉「联网补充」即为完全离线运行

---

## 踩过的坑（都写在代码注释里）

1. **IPv6 黑洞**：国内不少网络 IPv6 完全不通，Cloudflare 的 AAAA 连 0.01 秒就失败，而 .NET 默认先试 IPv6，一路耗到超时。
2. **多条 A 记录里有一条是死的**：串行重试会被第一条吃光预算，改成多 IP 并发竞速。
3. **系统代理规则不全**：代理开着但没覆盖 cnmeme 时，请求挂死到超时，比直连慢一个数量级 → 默认直连。
4. **别拿搜索列表第一条凑数**：搜 `yyds` 时 cnmeme 会返回一堆热门梗，随手取第一条会答成「我们不说XX」。
5. **别等最慢的源**：三个源 `WhenAll` 会让用户等最慢那个，改成竞速 + 首条后 2 秒宽限。

## 开发

插件是**源码形态**发布的（Alife 用 Roslyn 现编译），所以仓库里就是 `.cs` 源码：

```
presents.MemeWiki/
├── MemeWikiModule.cs    模块入口 + 6 个 AI 函数 + 查询编排
├── MemeWikiConfig.cs    配置项
├── MemeStore.cs         词库加载与检索（内存索引）
├── MemeOnline.cs        三个在线源（并发竞速、缓存）
├── MemeSync.cs          增量同步
├── MemeUserTerms.cs     自定义词条持久化
├── MemeRender.cs        回答文本拼装
├── MemeText.cs          归一化 / HTML 转文本 / 分段 / 编辑距离
├── MemeModels.cs        数据模型
├── Ipv4Connect.cs       IPv4 并发竞速连接
├── manifest.json
└── Resources/memes.json.gz
```

编译：放进 `Storage/Plugins/` 后由客户端编译，或用 Alife SDK 的 `dotnet build`（宿主程序集引用需指向客户端目录）。

词库重建：`_tools/build-memewiki-data.py`（把 cnmeme 导出的 `memes.db` 压成 `memes.json.gz`）。
